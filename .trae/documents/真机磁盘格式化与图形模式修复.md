# 真机磁盘格式化 / VGA 字体 / 图形模式 修复计划

## Context（背景与目标）

当前 ATA 驱动把磁盘硬编码在 legacy IDE 主通道 `0x1F0`；`fat32Format` 又固定 64MB/2048 的几何。因此在真机（DELL，SATA/AHCI）和 VMware（SCSI 虚拟盘）上，目标盘都不在 `0x1F0`，导致 `ataWriteSector` 失败 → **无法格式化**（问题1）。磁盘不可用又使 `/system`（含 font.bin）无法写入/读取 → **VGA 字体丢失**（问题2）。而为了修之前黑屏把 GRUB 设成 `gfxpayload=text`，真机没有 Bochs VBE 端口 → 无帧缓冲 → **进不了图形模式**（问题3）。

用户已确认方向：
- **磁盘**：新增磁盘抽象层，枚举 PCI 上的 AHCI(SATA) 与 legacy IDE 控制器，解析 MBR 分区表，安装向导加"选磁盘→选分区→确认格式化"，`fat32Format` 参数化到目标分区。
- **图形/文本**：GRUB 提供 32bpp 帧缓冲（`gfxpayload=keep`），启动时若检测到引导器帧缓冲则用 `vgaSetFramebufferOutput` 把文本菜单画到帧缓冲；无帧缓冲回退 VGA 文本平面。文本渲染统一用 font.bin + 固定调色板，消除真机/VMware/VirtualBox/QEMU 的字体与颜色差异。

### 已验证的关键事实
- fat32 内部读写已用"含 partitionOffset 的整盘绝对 LBA"（例：[fat32WriteFatEntry](src/kernel/fs/fat32.c#L146-L157)），只有底层端口原语是全局 ATA → **替换原语、不改数学**。
- [fat32Format](src/kernel/fs/fat32.c#L1069-L1146) 硬编码 `FMT_TOTAL_SECTORS=131072`(64MB)、`FMT_PART_OFFSET=2048`、写 MBR 与 BPB，全部走全局 `ataWriteSector`。
- [pci.c](src/drivers/usb/pci.c#L92-L132) 已有 `pciScanBus/pciFindController`，但只解析 BAR0、`pciFindController` 硬编码 class 0x0C；AHCI 需 BAR5(offset 0x24) 与餐饮 class 0x01。
- [kernel.c graphic_main](src/kernel/kernel.c#L559) 已会 `mb2FindFramebuffer → vbeUseBootloaderFramebuffer → vbeSetMode`，保持现状即可。
- [vga.c](src/lib/stdio/vga.c) 已有 `vgaSetFramebufferOutput(bool)` 可在引导器帧缓冲上渲染文本（调用 `vbeFbTextCell` 等）；`gMb2Info` 在 kernel_main 保存。

### 重要依赖/风险（必须告知用户）
- **启动介质读取**：当前 `readCdFile`（install.c）靠 legacy ATAPI 0x170 + iso9660 读字体与 SYSTEM。真机若用 Rufus **USB-DD** 引导，USB 盘不会出现在 ATAPI 0x170 上 → 内核读不到 SYSTEM/font.bin。本计划先解决磁盘枚举与格式化；**USB/ATAPI 启动介质的文件读取作为后续独立工作**（推荐后续把 ATAPI 与 USB 存储都挂到新的 dDrive 抽象）。

## 实现步骤（建议分阶段落地，每阶段 QEMU 可验）

### 阶段 1：基础能力
1. `src/include/mm/paging.h` 增加 `#define PAGE_PCD 0x10`、`#define PAGE_PWT 0x08`（AHCI DMA 免缓存用）。
2. `src/drivers/usb/pci.h/pci.c` 补齐导出：
   - `int pciFindMassStorage(pciDevice*, uint8_t subclass, uint8_t progIf);`（baseClass 固定 0x01，复用 `pciScanBus` 逻辑）
   - `uint32_t pciReadBar32(const pciDevice*, uint8_t barOffset);`
   - `uint32_t pciGetBarSize(const pciDevice*, uint8_t barOffset);`
   - 宏：`PCI_CLASS_MASS_STORAGE`/`PCI_SUBCLASS_IDE`/`PCI_SUBCLASS_SATA`/`PCI_PROGIF_AHCI`。

### 阶段 2：磁盘抽象层（新文件）`src/drivers/disk.h`、`src/drivers/disk.c`
- 对象 `dDrive`：`{ DriveType type; bool present; uint32_t capacityLba; uint16_t baseIO; uint8_t driveSel; uintptr_t abar; uint8_t port; Partition parts[4]; int partCount; }`；`MAX_DRIVES=8`、全局 `gDrives[]`。
- `Partition { uint32_t startLba,numSectors; uint8_t type,bootable,slot; }`。
- 接口：
  - `void diskInit(void)`；`int diskGetCount(void)`；`const dDrive* diskGetDrive(int idx)`；
  - `int driveReadSectors(drv,lba,cnt,buf)` / `driveWriteSectors(drv,lba,cnt,buf)`（LBA 为整盘绝对 LBA）；
  - `int diskScanPartitions(drv)`：读 LBA0，区 0x55AA，解析 446+16*i 的 4 条主分区（type/start/size）；
  - `void mbrSetEntry(uint8_t* sec,int slot,const Partition*)`：写 bootable/CHS/type/start/size + 0x55AA。
- **PIO IDE 后端**：把 [ata.c](src/drivers/ata.c) 逻辑参数化到 `(baseIO, driveSel)`；探测 `0x1F0`/`0x170` 两通道 master+slave，用 `IDENTIFY(0xEC)` 判定存在并取容量（Word60/61）。`ata.[ch]` 保留给旧调用过渡。

### 阶段 3：AHCI 后端（新文件）`src/drivers/ahci.h`、`src/drivers/ahci.c`
- `ahciProbe()`：`pciFindMassStorage(&dev,0x06,0x01)` → `BAR5=pciReadBar32(&dev,0x24)` → 按 [xhci.c MMIO 映射](src/drivers/usb/xhci.c) 逐页 `pagingMapPage(addr,addr,PRESENT|WRITABLE)` identity 映射 → 复位 `GHC=abar+0x04`(bit31 复位→等清零→`AE=1`) → 读 `PI=abar+0x0C` 找活动端口，填 `dDrive`。
- 端口引擎：`portBase=abar+0x100+0x80*port`；命令列表(CLB, 256B 对齐)、命令表、接收 FIS(FB, 256B)。启动：清 `FR/CR/ST`→写 `PxCLB/PxFB`→置 `ST` 等 `FR`。
- 一次读写：命令头 `CFL=5、PRDTL=1、W、PRDBC=cnt*512`；CFIS `D0=0x27(读)/0x37(写)`、`D1=((lba&0xFF)<<24)|((lba&0xFF00)<<8)|((lba&0xFF0000)<<8)|((lba>>16)&0xFF)...` 拼 48 位 LBA 与 count；PRD `DBA=物理 DMA 地址`、`DBC|=(cnt*512-1)`；写 `PxCI` 置位并忙等 `PxIS`/`PxTFD`。
- **DMA 缓冲**：命令表/PRD/数据缓冲从 `pmmAllocPages` 分配，页映射加 `PAGE_PCD|PAGE_PWT`；`pmmAllocPages` 返回虚拟=物理（identity），直接 `(uint32_t)buf` 作物理地址。

### 阶段 4：FAT32 参数化 `src/kernel/fs/fat32.h`、`fat32.c`
- `fat32Volume` 新增 `const dDrive* drive;`。
- 签名：`bool fat32Init(vol, const dDrive* drv);`、`bool fat32Format(vol, const dDrive* drv, uint32_t partStartLba, uint32_t partNumSecs);`；同步 `extern fat32Volume fsVolume;`（[fat32.h](src/kernel/fs/fat32.h)）。
- 机械替换全文件 34 处 `ataReadSector/ataWriteSector`（含 `fmtWriteFatCluster`）→ `driveReadSectors/driveWriteSectors(vol->drive, ...)`；把 `fmtWriteFatCluster` 加 `const dDrive*` 参数。
- `fat32Format`：用参数 `partStartLba/partNumSecs` 取代 `FMT_PART_OFFSET/FMT_TOTAL_SECTORS-FMT_PART_OFFSET`；MBR 用 `mbrSetEntry`；`hiddenSectors=partStartLba`、`totalSectors32=partNumSecs`；`vol->drive=drv; vol->partitionOffset=partStartLba;`。保留 `FMT_SPC/32、FMT_RESERVED/128...` 等几何常量。
- `fat32Init`：`vol->drive=drv`；读 LBA0 解析分区（优先 bootable 且 type==0x0C，否则首个非空），`vol->partitionOffset=<startLba>`；无分区=superfloppy(0)。

### 阶段 5：安装向导改造 `src/kernel/install.c`
- 新增模块级 `gInstDrive/gInstPart/gInstPartValid`。
- `installWizardNotFormatted()` 开头、问"是否格式化"前插 `selectDiskPartition()`：
  - `chooseDrive()` 列出 `diskGetCount()` 的非空盘；`choosePartition(d)` 对选中盘 `diskScanPartitions` 后列出；`confirmFormat()` 显示 `Disk#/Partition n type=0x0C start=.. size=..`。复用 `instDrawPage/instAsk`（VGA_HEIGHT=25），数字键或上下键+回车选择，`Backspace` 回退上一级；无可用盘则 `INST_RESULT_RUN_CD`。
  - 每行串口镜像打印（`putDec32` 输出 start/size）供无头验证。
- `installSystem()`：`fat32Format(&fsVolume, gInstDrive, gInstPart.startLba, gInstPart.numSectors)` → `installWriteGrub()` → `fat32Init(&fsVolume, gInstDrive)` → `installBootFiles()`。
- `installWriteGrub()`：写完 grub MBR 后用 `mbrSetEntry(mbr,0,&gInstPart)` 补写分区条目再经 `gInstDrive` 写回扇区0；`core.img` 写盘换抽象层；**守卫**：`gInstPart.startLba > GRUB_SECTOR_START + coreSectors`。
- `writeDiskFile/installCopySystem/clearSystemDir` 已用 `&fsVolume`，自动落选中盘，不改。

### 阶段 6：kernel_main 接线 `src/kernel/kernel.c`
- `diskInit()`（新）→ `atapiInit()` → 取 `drv=(diskGetCount()>0)?diskGetDrive(0):NULL` → `fat32Init(&fsVolume, drv)` → 成功/失败输出 `[FAT32] ...`。
- 启动控制台帧缓冲（`gMb2Info=addr` 后）：
  ```
  MbFbInfo fb;
  if (addr && mb2FindFramebuffer(addr,&fb)==0 && fb.bpp==32)
      if (vbeUseBootloaderFramebuffer(fb.addr,fb.pitch,fb.width,fb.height,fb.bpp)==0)
          vgaSetFramebufferOutput(true);   // 后续菜单画到 fb
  ```
  帧缓冲激活时确保 `loadFontFromCdIntoVbe()`（RUN_CD）或 `loadFontIntoVbe()+loadCjkFontIntoVbe()`（BOOT）被调用。
- `graphic_main` 保持现状。

### 阶段 7：GRUB 与字体/调色板
- `tools/grub_cd.cfg`、`grub_hdd_memdisk.cfg`：`set gfxpayload=text` 改为 `insmod vbe / insmod vga / set gfxmode=1024x768x32 / set gfxpayload=keep`（须显式 `gfxmode` 才有 fb tag；失败时 GRUB 自动回退文本）。
- 固定 VGA16→RGB32 调色板 `kVgaRgb[16]`（标准色 0x00RRGGBB），供帧缓冲文字渲染取色，避免硬件 VGA 属性差异（真机/VMware/VirtualBox/QEMU 字体颜色统一、选中闪烁一致）。

### 构建与验证
- 构建：Makefile 自动扫描 `src/**/*.c`，新增文件无需改清单；`wsl -- bash -lc 'cd ... && make kernel.bin && bash tools/build_wsl.sh'`。
- QEMU 三场景：
  1. legacy IDE 全流程（`-machine pc -hda disk.img`）选盘→分区→格式化→`[INSTALL]`→重启从 disk.img 引导。
  2. AHCI（`-machine q35 -device ich9-ahci -drive ...ide-hd,file=disk.img`）同流程走 `ahciReadSectors`。
  3. 帧缓冲（q35 + `-vga std`）下文本菜单显示、选 Graphic 后 `[G] use bootloader fb → vbeSetMode ok` 进入图形桌面。

## 明确不在本次范围（标注风险，待后续）
- USB/ATAPI 启动介质（Rufus USB-DD 引导）下由内核读取 SYSTEM/font.bin —— 需把 ATAPI 与 USB 存储挂到 dDrive 抽象后另行处理；在此之前真机 USB-DD 引导的"从 CD 读文件"路径仍受限。
